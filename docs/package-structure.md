# Package structure

How a package's files map to upstream, patches, and build output.

- `packages/<name>/package.yaml` — where a tracked chart's upstream comes
  from (`url`, `subdirectory`, `chartRepoBranch`/`commit`, `version`,
  `packageVersion`, `workingDir`, `additionalCharts`). See
  [packages/README.md](../packages/README.md). Use the `onboard-new-package`
  skill for the end-to-end checklist when adding a brand-new forked package
  (it sequences `updatecli-add-package`/`kyverno-policy-fix` rather than
  duplicating them). `packageVersion` must move in step with whatever else
  changed, for every package — forked or from-scratch `url: local` alike:
  reset to `01` when `url`/`commit` itself changed (a real new upstream
  release — never applies to a `url: local` package), otherwise strictly
  bumped — every published chart version has to be unique and immutable, so
  a patch-only change (e.g. from `kyverno-policy-fix` editing
  `local-chart/` or a forked package's `base.values.yaml`, or from
  `resolve-upstream-bump-conflict`) needs its own new `packageVersion` even
  when there's no upstream move behind it. `make check-package-version
  PACKAGE=<name>` and the `package-version-bump` CI job enforce this on
  every PR; `updatecli`'s own automated bumps already comply (see
  `common.packageBuildVersion` in `updatecli/updatecli.d/_common.yaml`).
- `packages/<name>/generated-changes/` — the patch set on top of upstream,
  (re)generated by `make patch`. This — not the working chart tree — is what
  actually lives on `main` for forked packages.
- `packages/<name>/charts/` **or** `packages/<name>/local-chart/` — the
  unarchived, patched chart working tree. Which directory a package uses is
  read from `package.yaml`'s `workingDir` field via `scripts/chart-dir.sh`
  (never assumed) — every target and script goes through that script rather
  than hardcoding a path.
  - Forked packages (have a `url:`) omit `workingDir` and default to
    `charts/`, pulled fresh from upstream by `make prepare`. The repo's
    `.gitignore` has a blanket `/packages/**/charts/` rule, so this
    directory is **build output, never committed**.
  - **From-scratch packages** (no upstream `url:` — currently
    `network-policies`, `kyverno-pod-policies`, `kyverno-cluster-policies`)
    set `workingDir: local-chart` explicitly and write the chart directly in
    this repo; `local-chart/` is real source and **is committed**.
- `charts/` (repo root) and `assets/` — build output of `make charts`
  (archived `.tgz`s + `index.yaml`), gitignored on `main`, regenerated by CI
  on merge and pushed to GHCR. Nothing to commit after running `make charts`
  locally.

See also: [values file layering](values-layering.md) (lives alongside these
same working-tree files).
